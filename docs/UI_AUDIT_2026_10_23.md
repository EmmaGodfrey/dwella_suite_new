Date: 23 October 2026. Status: refined after user feedback; drawers restored, full-page setup retained. Local verification recorded below.

[Start the Figma review](https://www.figma.com/design/aHlQPzHBsvGR4rNoabRQyW/Dwella-Suite?node-id=143-4109).

The user requested an audit of the current pages, particularly the bare getting-started checklist and long forms, followed by Figma designs before app changes. They also requested that Figma follow recorded product decisions and the current implementation, using Identity checks as an example.

## Evidence and scope

- Read all registered routes, shared layout/form styles, implemented form components, relevant backend onboarding fields, project feedback and existing Figma references.
- Inspected 22 main app routes in a real browser using a scratch database and fictional records. Added detail-page and form inspection for users, workspaces, Outreach contacts, properties, tenants, leases, invoices, receipts and maintenance; also inspected login and beta-closed registration.
- Checked Get started, Reports, Identity checks and Outreach settings at 390px, 720px and 2149px widths. These are mobile and viewport equivalents of 200%/67% zoom, rather than browser zoom automation. None of those checks showed document-level horizontal overflow.
- Inspected current setup in dark mode. Figma includes light/dark mobile checklist and a mobile validation example.
- Browser evidence: ignored `output/playwright/ui-audit-*.png`, `ui-audit-browser.json`, `ui-audit-details.txt`, `ui-audit-responsive.txt`. Reusable design helpers: ignored `output/ui-audit-figma-helpers.js`.
- The old scratch database initially lacked the latest migrations. Applied those only to the scratch database, seeded fictional portfolio/Outreach records, then repeated the main-route pass. Temporary support sessions were ended. No emails were sent.

This is a layout and consistency audit, not an authorization/security review or a complete regression test. Browser screenshots show representative populated/empty states; they do not exhaust every permission and asynchronous state.

## Form decisions

The user approved implementation, then clarified on 23 October 2026 that this is a refinement of the existing design, not an overhaul. That clarification supersedes the first full-page form pass. Drawers are the default; long forms use steps inside the drawer. Only workspace Setup remains a full-page task. Preserve the parent list/detail page, filters and scroll position while the drawer is open. Closing a drawer discards its local draft as before; new persistent drafts, URL history or refresh recovery are not introduced by this change.

Use steps for a sequence of distinct tasks, rather than splitting every form solely by field count. Related fields share rows on desktop and stack in reading order on mobile. Labels stay above controls. Long text, address and notes can span a row.

| Form | Accepted structure |
| --- | --- |
| Workspace setup | Full page on `/setup`, existing 3 steps, clearer surface and related-field rows |
| Add tenant with lease | Drawer: Tenant → Lease → Review; tenant-only skips Lease |
| New lease | Drawer: Tenant and unit → Terms, including status on the final step |
| Maintenance request | Drawer: Issue and location → Access and photos; no partial review block |
| Outreach contact | Add/edit drawer: Contact → Context → Source |
| Create workspace | Drawer: Owner and contact → Location and defaults |
| Property | Original add/edit in-panel form on Properties; retain grouped sections and field errors |
| Unit | Existing compact grouped form |
| Record payment | Plain drawer, paired amount/method and date/reference; invoice stays mounted |
| Create user | Plain grouped drawer; account type reveals the appropriate access fields |
| Beta signup/vendor/profile/identity submission | Keep short grouped forms; no additional wizard needed |
| Outreach settings/templates/sequence editor | Keep task-based settings/editor sections; do not turn repeated editing into a mandatory wizard |
| CSV import | Preserve existing preview/confirmation workflow |
| Identity decision/support reason/destructive confirmations/2FA | Keep focused controls and existing confirmation behavior |
| Registration | Paired first/last names retained; server-controlled availability unchanged |

Implementation must preserve values when moving between steps, validate the current step before advancing, return server errors to the affected step, focus the invalid control, support keyboard operation and prevent double submission. Creation remains a final action; navigating a step must not create partial records. Setup's existing browser-tab draft behavior remains intact; do not invent persistence for other forms without implementing it.

## Implementation and validation

Retained the Get started surface/progress, Identity summary fix, signup first/last-name row, paired fields, grouped Outreach settings and validation helpers/tests. Removed all full-page swaps inside the existing list/detail pages and removed the `AdminDrawer fullPage` option. The original property branch and `.dwella-property-form*` styles are used again, so they are retained rather than deleted as dead code.

The shared `FormDrawer` keeps Fluent's existing overlay, focus trap, Escape dismissal and body scrolling, with a compact step indicator and fixed footer. Back retains values; current-step validation and final all-field validation remain. Earlier-step server errors return to the owning step. Closing restores focus to the connected opener without changing scroll. Pending submissions disable fields and dismissal. No record is created by Continue.

New lease now has two steps, with status on Terms. The nested unit grid was removed. Maintenance keeps access/photos as its second input step and no longer has a partial review underneath it. Photo guidance derives from the existing constants. Shared admin intro notes only appear on the first step. Restored unchanged source blocks to their original formatting, reducing review noise; no blanket formatting pass was used for this correction.

Figma uses the existing native field/button instances and tokens. The drawer frames retain the original IDs and show the parent screen beneath the overlay; property uses its existing panel. Setup remains a full page, without a Cancel loop, and keeps Back/tab drafts. Receipt examples retain the actual RCT prefix. Static references document accepted structure and product scope; they do not claim pixel-perfect parity for every state. The hidden old third lease step is superseded by the two drawer steps.
